# Шахматная академия 2000

Персональная платформа подготовки к 2000 Rapid. Основной источник требований — [утверждённое ТЗ v1.0](CHESS_2000_ACADEMY_SPEC.md). Работает этап 1: интерфейс, доска, авторизация и постоянное хранение. Последующие этапы пока не подключены.

**Бюджет: строго $0 в месяц.** Целевое размещение: **Render Free + Neon Free**. Приложение не создаёт облачные ресурсы, не вызывает платные API и не переключает тарифы. Sites/Cloudflare не используются.

Подробная инструкция без опыта программирования: **[подключение Render и Neon](docs/RENDER_NEON_FREE.md)**.

## Архитектура

React + TypeScript + chess.js → Express 5 → PostgreSQL Neon через `pg`. Express отдаёт клиент и API на одном домене. Локальная SQLite сохранена для разработки и переноса старых данных. На Render нет зависимости от локального диска, при отсутствии `DATABASE_URL` сервер останавливается.

Для публичного Render-проекта владелец создаётся из защищённых переменных `OWNER_LOGIN` и `OWNER_PASSWORD`. Публичная регистрация закрыта. Существующий профиль при повторном запуске не перезаписывается. После первого успешного входа обе начальные переменные можно удалить из Render.

## Локальная разработка

Нужен Node.js 24.19.0, версия закреплена в `.node-version` и настройках Render.

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
```

Без `DATABASE_URL` используется прежняя `data/academy.sqlite`. Файл `.env` необязателен и не коммитится; пример настроек — [.env.example](.env.example). Нельзя передавать строку подключения или пароль в чат, Git, скриншоты и журналы.

Для PostgreSQL укажите `DATABASE_URL` в защищённых переменных среды. При первом запуске миграции применяются автоматически, в транзакции. Их также можно применить отдельно:

```sh
npm run db:migrate
npm run build
npm start
```

`npm start` требует PostgreSQL. Для проверки сборки исключительно локально со старой SQLite:

```sh
ALLOW_LOCAL_SQLITE=true npm start
```

Это исключение работает только при привязке к `127.0.0.1` и вне Render. Для Render оно запрещено.

## Переменные среды

| Переменная       | Значение / назначение                                               |
| ---------------- | ------------------------------------------------------------------- |
| `DATABASE_URL`   | Секретная строка подключения Neon PostgreSQL, обязательно на Render |
| `OWNER_LOGIN`    | Начальный логин: 3–40 латинских букв, цифр, «\_» или «-»            |
| `OWNER_PASSWORD` | Уникальный начальный пароль: 12–128 символов; не пароль Chess.com   |
| `HOST`           | `127.0.0.1` локально, `0.0.0.0` на Render                           |
| `PORT`           | `3000` локально; на Render используется значение платформы          |
| `NODE_ENV`       | `production` на Render                                              |
| `COOKIE_SECURE`  | `true` для HTTPS; на Render включён принудительно                   |
| `DATABASE_PATH`  | Только локальная SQLite, по умолчанию `data/academy.sqlite`         |

`RENDER=true` платформа Render устанавливает автоматически. В тестах PostgreSQL допускается отключение TLS только для loopback через `PG_TEST_ALLOW_INSECURE_LOCAL=true`; на Render это исключение не работает. Для удалённой базы проверка сертификата всегда включена, в том числе если строка подключения содержит `sslmode=require`.

## Проверка

```sh
npm run build
npm test
npm run test:e2e
npm run test:postgres
```

Последняя команда поднимает **настоящую PostgreSQL локально**, не создавая облачную базу, выполняет API-тесты, перенос SQLite, проверку отдельного production-процесса после перезапуска и браузерные тесты с PostgreSQL. Тестовая PostgreSQL привязана к loopback, временные данные удаляются только после завершения тестов. Рабочая SQLite не затрагивается.

Браузерные тесты используют `/usr/bin/chromium`, если он установлен. Другой путь задаётся через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. На машинах без Chromium установите браузер Playwright: `npx playwright install chromium`. Скриншоты и диагностика сохраняются в игнорируемый `test-results/`.

## Что сохранено

- Русскоязычный адаптивный Chess Performance с утверждённой палитрой и десятью разделами.
- Интерактивная доска: допустимые ходы, обе ориентации, рокировка, взятие на проходе, четыре варианта превращения, шах, мат и ничейные состояния.
- Нотация, просмотр полуходов, отмена и подтверждаемый сброс.
- Сохранение каждого хода и заметок на сервере, восстановление после перезагрузки и повторного входа.
- scrypt-хеши паролей, HttpOnly/SameSite cookies, авторизация личного API, ограничение попыток входа, проверка происхождения запросов.
- Проверка версии доски при записи: устаревшая вкладка не затирает обновления.

UI и шахматная логика сохранены. Единственная текстовая правка в интерфейсе — общая подпись серверного хранения вместо упоминания SQLite, чтобы она подходила и для PostgreSQL.

## Перенос SQLite

Сначала сохраните резервную копию **всего каталога `data/` при остановленном приложении**, включая WAL-файлы, если они есть. Затем задайте `DATABASE_URL` **пустой** Neon-базы и выполните в среде, где находится исходный файл:

```sh
npm run db:import-sqlite -- --source data/academy.sqlite
```

Команда читает источник в режиме read-only и переносит профиль, пароль, доску, заметки и хеши сеансов в одной транзакции. Она сравнивает все перенесённые поля, отменяет транзакцию при расхождении и отказывается перезаписывать непустую целевую базу. Сеанс браузера на другом домене потребует нового входа, пароль сохранится. Исходная SQLite **никогда не удаляется**.

На текущей рабочей базе пока нет владельца и сохранённых досок, поэтому переносить реальные пользовательские записи сейчас не требуется. Сам механизм проверен на отдельной базе с непустыми данными. Если источник содержит нулевой символ, неподдерживаемый PostgreSQL, перенос останавливается без изменений: сначала исправьте соответствующую заметку локально, ничего автоматически не отбрасывается.

## Ограничения и следующие этапы

Render Free и Neon Free могут засыпать и приостанавливать обслуживание при исчерпании бесплатных квот. Нет SLA и обещания круглосуточной доступности. Платные планы не включаются приложением. Проверка Render `/api/health` не обращается к базе; ручная `/api/ready` проверяет подключение. Фонового поддержания активности нет, пул ограничен двумя соединениями и закрывает простаивающие через 10 секунд.

Персональная база Neon и сервис Render в этой сессии не созданы: доступ к аккаунтам/строке подключения не предоставлен. Проверки локальной PostgreSQL не выдаются за облачную публикацию.

Chess.com, Stockfish, тренажёры, ежедневный план и гибридный тренер остаются следующими этапами. Для них зафиксирован бюджет $0: публичный Chess.com API, Stockfish в браузере по кнопке, алгоритмические русские рекомендации без платной языковой модели. На этом шаге они не реализуются.
