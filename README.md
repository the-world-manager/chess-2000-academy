# Шахматная академия 2000

Персональная платформа подготовки к 2000 Rapid. Основной источник требований — [утверждённое ТЗ v1.0](CHESS_2000_ACADEMY_SPEC.md). Реализован **этап 1: основа**. Полная платформа по критериям приёмки ещё не готова.

## Запуск

Нужен **Node.js 24** (используется встроенный `node:sqlite`). Все команды из корня репозитория:

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
```

Разработка: один сервер Express с Vite middleware, порт 3000. Для подготовленной сборки:

```sh
npm run build
npm start
```

По умолчанию слушается только `127.0.0.1`. Публичные ссылки и публикация в текущем этапе не создавались. При первом открытии создайте аккаунт владельца (это отдельный аккаунт академии, не пароль Chess.com). Создавать его нужно **до предоставления публичного доступа**. После первого владельца регистрация закрывается. Отдельного демонстрационного аккаунта нет.

Переменные среды (секретных значений для запуска не требуется):

| Переменная      | По умолчанию                     | Назначение                                                             |
| --------------- | -------------------------------- | ---------------------------------------------------------------------- |
| `HOST`          | `127.0.0.1`                      | Адрес привязки; для контейнера можно установить `0.0.0.0`              |
| `PORT`          | `3000`                           | Порт HTTP                                                              |
| `DATABASE_PATH` | `data/academy.sqlite`            | Файл постоянной базы; относительный путь считается от каталога запуска |
| `COOKIE_SECURE` | `false`                          | При размещении через HTTPS обязательно `true`                          |
| `NODE_ENV`      | устанавливается командой `start` | В production Express отдаёт `dist/`                                    |

## Что работает

- Адаптивный русскоязычный интерфейс Chess Performance с утверждённой палитрой и десятью разделами навигации.
- Главная с честными пустыми состояниями. 1437 обозначен стартовой точкой, не текущим рейтингом.
- Доска: выбор фигуры и клетки, допустимые ходы, обе ориентации, рокировка, взятие на проходе, выбор любой фигуры превращения, шах, мат и ничейные состояния.
- Полная нотация текущей рабочей партии, просмотр любого полухода, отмена и подтверждаемый сброс партии.
- Каждый ход сохраняется на сервере. Заметки сохраняются отдельной кнопкой. Сброс доски не удаляет заметки.
- SQLite: профиль, учётная запись, хеши сеансов, FEN, PGN, версия позиции, заметки. Данные восстанавливаются после перезагрузки, повторного входа и перезапуска сервера.
- Вход/выход владельца, scrypt для паролей, HttpOnly/SameSite cookies, проверка происхождения запросов, ограничение попыток входа, авторизация всех личных API.
- Оптимистическая блокировка: устаревшая вкладка получает конфликт вместо перезаписи чужого обновления.

Доска управляется кликами/касаниями и клавиатурой через доступные кнопки, без перетаскивания. Сохраняется одна рабочая партия владельца, **это ещё не журнал импортированных партий**. SAN сохраняется в стандартной шахматной нотации; это разрешённые ТЗ обозначения.

## Проверка

```sh
npm run build
npm test
npm run test:e2e
```

Браузерные тесты используют системный `/usr/bin/chromium`, если он установлен. Альтернатива — `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` либо браузер Playwright (`npx playwright install chromium`). Для последнего необходим сетевой доступ к доменам распространения Playwright; в текущей среде используется системный браузер.

Тесты API создают временные базы и действительно закрывают/повторно открывают сервер с тем же файлом. E2E запускает production-сборку на порту 3100 с отдельной базой в `/tmp`, проверяет вход, ходы, историю, заметки, перезагрузку, повторный вход, отсутствие горизонтального переполнения и необработанных ошибок JavaScript. Есть настольный и мобильный профиль Chromium. Скриншоты и диагностика находятся в игнорируемом `test-results/`.

## Данные и размещение

`data/` исключён из Git. Не удаляйте этот каталог при обновлении приложения. Для размещения нужен постоянный записываемый диск и сервер Node.js 24. База не выдаётся через HTTP; публичен только `dist/`. Нельзя публиковать корень репозитория как каталог статических файлов.

Для резервной копии остановите процесс и скопируйте **весь каталог `data/`**, включая файлы `-wal` и `-shm`, если они есть; затем запустите сервер. При восстановлении возвращайте каталог целиком с доступом только для пользователя сервера. Сеанс действует семь дней; выход отзывает его на сервере. Восстановление забытого пароля пока не реализовано — храните пароль в менеджере паролей. Перед открытием в интернете необходим HTTPS и `COOKIE_SECURE=true`.

**Sites:** в этой среде нет инструментов и документации платформы Sites. Совместимость исполнения Node.js и постоянного диска не проверена, публикации не было. Если Sites поддерживает только статические страницы, потребуется отдельное размещение API и базы. Заменять серверную базу на localStorage нельзя. React/Vite создаёт обычный статический клиент; выбор способа размещения API остаётся проверкой этапа публикации.

## Что дальше

- **Этап 2:** Chess.com Published Data API, актуальный рейтинг, архивы, дедупликация, журнал и воспроизведение импортированных PGN; настоящий Stockfish с измерением производительности, запуском исключительно по кнопке и сохранением результатов.
- **Этап 3:** координаты и статистика, проверяемые тактические задачи, расчёт, утверждённый дебютный репертуар, упражнения из реальных ошибок.
- **Этап 4:** конкретные ежедневные задания, фактическое время и выполнение, годовой план, недельные отчёты; гибридный тренер «Stockfish → алгоритмы → русские объяснения». Оценки движка и персональная статистика не генерируются языковой моделью.
- **Этап 5:** проверка всей цепочки, хостинг Sites, безопасная публикация и проверка постоянства диска на целевом хостинге.

Статус каждого критерия приёмки и архитектура описаны в [документации](docs/ARCHITECTURE.md).
