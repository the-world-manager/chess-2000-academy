# Архитектура и границы этапа 1

## Принятые решения

Утверждённый стек сохранён: React + TypeScript, chess.js, серверное API, постоянная база. Конкретизация для первого этапа: Vite + Express 5 + SQLite через `node:sqlite` Node.js 24. SQLite подходит для одного владельца и транзакционного сохранения; отдельный сервис базы сейчас не нужен. Привязка данных через `user_id` позволяет расширить модель позднее, но многопользовательская регистрация пока намеренно закрыта.

Клиент и API имеют один origin. В разработке Vite работает как middleware Express; в production Express отдаёт собранный клиент. Маршрутизация разделов через hash сохраняет открытый раздел после перезагрузки без внешнего маршрутизатора. API — единственный источник сохранённого состояния, localStorage для личных данных не применяется.

## Схема v1

- `users`: логин, соль и scrypt-хеш пароля, Chess.com username, стартовый и целевой рейтинг, дата создания.
- `sessions`: SHA-256-хеш случайного 256-битного токена, владелец, срок действия. Сам токен хранится только в HttpOnly cookie браузера.
- `board_states`: владелец, PGN, FEN, заметка, версия записи и дата обновления.

WAL и foreign keys включены. Все запросы используют параметризованные выражения. Сервер восстанавливает игру из PGN, сам проверяет ход и сохраняет FEN/PGN вместе одним UPDATE. Версия записи проверяется и в UPDATE, чтобы не перетирать изменения. Нельзя записать произвольный FEN или готовую партию через API текущего этапа.

Таблицы импортированных партий, анализов, критических позиций, упражнений/результатов, ежедневных планов/выполнения, недельных отчётов и дебютного прогресса будут добавляться версионированными миграциями в соответствующих этапах. Пустые таблицы не выдаются за готовые подсистемы.

## API

| Метод | Путь           | Назначение                                                                      |
| ----- | -------------- | ------------------------------------------------------------------------------- |
| GET   | `/api/health`  | Доступность сервера                                                             |
| GET   | `/api/auth`    | Состояние первичной настройки и текущего входа                                  |
| POST  | `/api/setup`   | Создание первого владельца; затем закрыт                                        |
| POST  | `/api/login`   | Выдача cookie сеанса                                                            |
| POST  | `/api/logout`  | Отзыв текущего сеанса                                                           |
| GET   | `/api/profile` | Личный профиль; только после входа                                              |
| GET   | `/api/board`   | Сохранённая доска и заметка; только после входа                                 |
| POST  | `/api/board`   | Действие `move`, `undo`, `reset` или `notes`, обязательна актуальная `revision` |

Ошибка 409 означает конфликт версии, 400 — неверные данные или незаконный ход, 401 — необходимость входа, 403 — запрос с другого сайта. Данные при сетевой ошибке не перезаписываются, UI показывает русскую ошибку и повторную загрузку. Заметки отправляются только по явному сохранению.

## Stockfish и тренер

На первом этапе не подключены. Автоматического анализа при открытии страницы, ходе или сохранении нет. Вторая стадия должна реализовать отдельное явное действие «Анализировать партию», реальные результаты движка и их кеширование. Оценка подходящего серверного/WASM-варианта требует теста на целевом хостинге.

Гибридный тренер остаётся трёхкомпонентным: Stockfish даёт оценки и варианты, алгоритмы считают статистику и нагрузку, языковая модель объясняет подтверждённые результаты по-русски. Сейчас главная содержит только явно обозначенную стартовую рекомендацию, не персональный анализ.
