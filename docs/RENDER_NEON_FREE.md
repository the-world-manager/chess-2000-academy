# Публикация на Render Free и Neon Free: пошаговая инструкция

Инструкция подготовлена 23 октября 2026 года. Бюджет проекта — **строго $0**. Приложение не создаёт ресурсы через API и не выполняет изменение тарифа. Всё ниже относится к ручному подключению вами бесплатных аккаунтов.

Если на каком-либо шаге вместо Free предлагается платный план, пробный платный период или обязательное подключение списаний — **остановитесь, ничего не подтверждайте**. Не добавляйте платёжную карту ради этого проекта, не выбирайте автоматическое повышение тарифа. Настройки бюджета в платном аккаунте не заменяют выбор Free.

## Что получится

```text
Браузер → HTTPS Render Free → Express + React → TLS → Neon Free PostgreSQL
```

Один веб-сервис и одна база. Отдельные серверы, диски Render, управляемая PostgreSQL Render, фоновые процессы и платные API не нужны. Локальный диск Render используется только для файлов программы, не для личных данных.

## 1. Откройте репозиторий GitHub

1. Войдите в GitHub под аккаунтом, которому принадлежит `the-world-manager/chess-2000-academy`.
2. Откройте [репозиторий](https://github.com/the-world-manager/chess-2000-academy).
3. В выбранной ветке должны быть файлы `render.yaml`, `package.json`, папки `server`, `migrations` и этот документ. Используйте ветку, указанную в итоговом отчёте Codex; не разворачивайте старую версию, где только README.
4. Код проекта можно хранить в закрытом репозитории. При подключении Render разрешите доступ только к этому репозиторию.

## 2. Создайте бесплатную базу Neon

1. Откройте [Neon](https://neon.com/) и зарегистрируйтесь, например через GitHub.
2. Убедитесь, что организация находится на тарифе **Free**, а не Launch, Scale или платном пробном тарифе. Проверьте страницу тарифа/оплаты. Не подключайте платёжный метод или автоматическое повышение тарифа.
3. Создайте один проект с названием `chess-2000-academy`.
4. Выберите ближайший доступный регион, который есть и у Render. Если сомневаетесь, выберите один и тот же европейский регион у обоих сервисов, когда он доступен бесплатно.
5. Оставьте одну основную ветку базы. Дополнительные ветки, реплики и платные возможности не нужны.
6. Оставьте автоматическое засыпание включённым. Если доступна настройка размера вычислений, выберите минимальный бесплатный размер, например 0,25 CU, без повышения платного лимита.
7. Откройте подключение к базе. Выберите созданную базу и роль, включите объединение подключений — адрес обычно содержит `-pooler`.
8. Скопируйте **строку подключения**, начинающуюся с `postgresql://`. В ней содержится пароль. Не копируйте окружающую команду `psql` или кавычки.
9. Сохраните строку в менеджере паролей до следующего шага. Не отправляйте её в чат или GitHub. Код использует TLS с проверкой сертификата; не пытайтесь отключать SSL при ошибке подключения.

По полученной официальной документации Neon Free на дату подготовки предусмотрены 100 CU-часов вычислений на проект в месяц, 1 ГБ PostgreSQL-хранилища на проект и 5 ГБ исходящего трафика на проект в месяц. После 5 минут простоя вычисления засыпают. При исчерпании CU-часов/трафика вычисления приостанавливаются, а не переключаются автоматически на платный план. При заполнении хранилища операции, увеличивающие его объём, могут отклоняться. Эти ограничения не удаляют данные.

Лимиты могут меняться: перед подтверждением проверьте их в своей консоли и [официальном описании Neon Free](https://neon.com/docs/introduction/plans). Бесплатные квоты не дают гарантии постоянной доступности.

## 3. Решите, требуется ли перенос старых данных

**В текущей рабочей SQLite владельца и сохранённых досок пока нет.** Если вы ещё не создавали профиль и не сохраняли заметки в другой копии проекта, переходите к шагу 4 — новая база начнёт работу с чистого состояния.

Если у вас уже есть личные данные в SQLite, сначала перенесите их. Не создавайте нового владельца в Neon до переноса: импорт в непустую базу специально запрещён.

1. Остановите старый экземпляр приложения, чтобы база перестала изменяться.
2. Сохраните отдельную копию всей папки `data/`, включая файлы `academy.sqlite-wal` и `academy.sqlite-shm`, если они есть.
3. В среде, где находится старая папка проекта, добавьте `DATABASE_URL` через защищённые настройки среды. Не вставляйте строку подключения в команду или чат. В локальной копии можно использовать игнорируемый файл `.env` по образцу `.env.example`.
4. Запустите в терминале проекта:

   ```sh
   npm ci
   npm run db:import-sqlite -- --source data/academy.sqlite
   ```

5. Дождитесь сообщения «Перенос проверен» с количеством владельцев, досок и сеансов. Команда сравнивает все перенесённые поля. При ошибке исходная SQLite остаётся на месте, неполные записи откатываются.
6. После публикации войдите со старым логином и паролем. Проверьте позицию, нотацию и заметки. После этого отдельно выполните проверку перезапуска из шага 7.
7. Не удаляйте старую базу даже после сообщения об импорте: оставьте резервную копию до собственной проверки сайта и следующего входа.

Если терминал вам незнаком, эту операцию можно поручить Codex после защищённого добавления `DATABASE_URL` в среду с исходным файлом. Сам пароль в чат присылать не нужно.

## 4. Создайте бесплатный веб-сервис Render

1. Откройте [Render](https://render.com/) и войдите через GitHub.
2. Выберите бесплатное рабочее пространство. Убедитесь, что для проекта не включены платный тариф рабочего пространства, автоматическое пополнение или списания.
3. Создайте **веб-сервис** из Git-репозитория. Не выбирайте статический сайт: приложению нужен Express API.
4. Подключите `the-world-manager/chess-2000-academy` и выберите ветку с новым коммитом из отчёта.
5. Укажите настройки:

   | Поле                         | Значение                                    |
   | ---------------------------- | ------------------------------------------- |
   | Название                     | `chess-2000-academy` или свободное название |
   | Среда исполнения             | Node                                        |
   | Корневая папка               | Оставить пустой: проект в корне репозитория |
   | Регион                       | По возможности тот же, что у Neon           |
   | Команда сборки               | `npm ci --include=dev && npm run build`     |
   | Команда запуска              | `npm start`                                 |
   | Тариф экземпляра             | **Free**, стоимость **$0**                  |
   | Количество экземпляров       | 1                                           |
   | Автоматическое развёртывание | Выключено                                   |
   | Проверка здоровья            | `/api/health`                               |

6. **Не добавляйте постоянный диск Render, отдельную базу Render, фоновый обработчик, расписание или масштабирование.** Они не нужны этой архитектуре и могут относиться к платным услугам.
7. Настройте секреты до первого запуска, как описано ниже.

Файл `render.yaml` содержит те же настройки и явный `plan: free`. Его можно использовать для развёртывания из конфигурации, если этот способ доступен в вашем бесплатном аккаунте, но ручной путь выше позволяет проверить каждое поле до создания сервиса. Конфигурация не выбирает платную услугу вместо бесплатной.

Текущие условия Render проверьте на странице [бесплатных сервисов](https://render.com/docs/free). В этой облачной среде запрос к render.com отклоняется сетевой политикой, поэтому фактические условия вашего аккаунта не проверены. Если бесплатное создание недоступно или требуется платное подтверждение, не продолжайте оплату.

## 5. Введите переменные Render

В разделе переменных среды веб-сервиса добавьте:

| Имя             | Что указать                                         |
| --------------- | --------------------------------------------------- |
| `DATABASE_URL`  | Секретная строка подключения, скопированная из Neon |
| `NODE_VERSION`  | `24.19.0`                                           |
| `NODE_ENV`      | `production`                                        |
| `HOST`          | `0.0.0.0`                                           |
| `COOKIE_SECURE` | `true`                                              |

`PORT` задаёт Render автоматически, вручную менять его не нужно. `RENDER=true` также задаётся платформой автоматически.

**Если вы начинаете с пустой базой:** добавьте ещё две переменные:

- `OWNER_LOGIN` — придумайте логин из 3–40 латинских букв, цифр, «\_» или «-».
- `OWNER_PASSWORD` — придумайте уникальный пароль длиной 12–128 символов и сохраните его в менеджере паролей. Это пароль академии, не Chess.com.

Первый запуск создаст владельца и доску в транзакции, пароль сохранится только в виде scrypt-хеша. Посторонний посетитель не сможет зарегистрироваться через публичный сайт раньше вас.

**Если вы перенесли старый профиль:** не задавайте `OWNER_LOGIN` и `OWNER_PASSWORD`; войдёте по прежним данным.

Никогда не задавайте на Render `ALLOW_LOCAL_SQLITE` или `PG_TEST_ALLOW_INSECURE_LOCAL`. Эти исключения предназначены только для локальной разработки/автоматических тестов; сервер дополнительно запрещает их применение на Render.

## 6. Запустите сборку и войдите

1. Перед подтверждением ещё раз убедитесь: один веб-сервис **Free**, Neon **Free**, платёжные методы не подключены.
2. Подтвердите создание/развёртывание бесплатного веб-сервиса.
3. Дождитесь успешной сборки и сообщения «Шахматная академия запущена» в журнале. Полную строку подключения и пароль в журнал копировать нельзя.
4. Render покажет реальный HTTPS-адрес вашего сервиса. Откройте именно его; в этой инструкции адрес не выдумывается.
5. Войдите с выбранным или перенесённым логином и паролем.
6. Откройте доску, выполните несколько ходов, сохраните заметку, обновите страницу. Ходы и заметка должны сохраниться.
7. Если новый владелец создан и вход успешен, удалите **обе** переменные `OWNER_LOGIN` и `OWNER_PASSWORD` из Render и сохраните настройки. Это может перезапустить сервис; аккаунт уже в PostgreSQL и не исчезнет. Эти переменные не являются средством сброса пароля существующего владельца.

## 7. Обязательная проверка перезапуска

1. Запомните текущую позицию и содержимое сохранённой заметки.
2. Выйдите из аккаунта, закройте вкладку и снова войдите. Проверьте данные.
3. В панели Render выполните обычный перезапуск сервиса, если он доступен. Если отдельной кнопки нет, вручную разверните ту же версию кода без изменения Neon.
4. Дождитесь восстановления сервиса, откройте сайт и при необходимости войдите повторно.
5. Сверьте позицию, историю ходов и заметки. Они должны сохраниться: PostgreSQL находится вне временного диска Render.
6. Дополнительно можно открыть путь `/api/ready` на адресе своего сайта. Ответ `{"ok":true}` означает, что сервер смог обратиться к базе. Это ручная проверка, не ставьте её на постоянный мониторинг.
7. Только после этого считайте облачное подключение проверенным. В текущей сессии выполнена аналогичная автоматическая проверка с настоящей локальной PostgreSQL; ваше облачное размещение ещё не проверялось.

## 8. Обновления и ограничения $0

- Render Free может останавливать неактивный веб-сервис. Первый запрос после простоя бывает медленным. Neon также просыпается после простоя. Дождитесь загрузки и повторите действие при понятной сетевой ошибке.
- Бесплатные квоты ограничивают вычисления, память, трафик и сборки. При исчерпании квоты нужно ждать её обновления или уменьшать нагрузку, **не переходить на платный план**.
- Нельзя постоянно пинговать сайт или базу ради обхода засыпания. В коде нет такого механизма. Проверка Render `/api/health` специально не обращается к Neon.
- Не включайте автоматическую оплату, пополнение, платные опции, платные резервные копии и расписания. Условия провайдеров могут меняться; сохранение $0 требует оставаться на Free.
- Нет гарантии круглосуточной доступности или коммерческого SLA. Для персональной разработки это приемлемый компромисс; обещать одинаковую скорость в любое время нельзя.
- Сохраняйте копию SQLite. Для новых данных используйте доступный бесплатный ручной снимок Neon, если он явно входит в ваш Free, либо бесплатный локальный `pg_dump`. Не выбирайте платную услугу резервного копирования. Не публикуйте резервные копии с личными данными.
- Восстановление забытого пароля и многопользовательская регистрация пока не реализованы.
- Stockfish, импорт Chess.com, тренажёры и тренер на этом шаге не добавляются. Их следующий вариант должен работать без платных API и серверных вычислений: браузерный Stockfish и алгоритмические объяснения.

| Ситуация                                     | Что сделать                                                                                                             |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Не видны файлы программы на GitHub           | Выберите ветку с коммитом из отчёта                                                                                     |
| Нет Free или указана стоимость выше $0       | Остановитесь, не подтверждайте платное создание                                                                         |
| Приложение не запускается                    | Проверьте Node 24, `DATABASE_URL`, значения первоначального владельца и журнал без публикации секретов                  |
| Ошибка подключения PostgreSQL                | Проверьте строку Neon, пароль и доступность бесплатной квоты; TLS не отключать                                          |
| Появилась форма создания владельца на Render | Начальная настройка/перенос не завершены; не открывайте регистрацию, проверьте переменные и базу                        |
