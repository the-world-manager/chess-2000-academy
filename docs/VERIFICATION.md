# Проверка этапов 1–2

Дата: 23 октября 2026 года. Node.js 24.19.0, production-сборка Vite, системный Chromium (desktop и профиль телефона). Никаких платных ресурсов не создано.

## Итог автоматического прогона

| Команда | Результат |
| --- | --- |
| `npm run build` | TypeScript и production Vite — успешно |
| `npm test` | 16/16, SQLite, API/авторизация/правила/импорт/анализ |
| `npm run test:e2e` | 8/8, desktop + mobile Chromium |
| `npm run test:postgres` | 18/18 серверных + 8/8 браузерных + 2/2 с реальной сохранённой партией |
| `npm run test:live` | Настоящий Chess.com API + 2/2 браузерных теста реальной партии |

Это 54 успешных выполнения тестов, часть одних и тех же сценариев повторяется на разных хранилищах. PostgreSQL 18.4 запускается локально во временном изолированном кластере; это настоящая PostgreSQL, не подмена SQLite. Тесты включают перенос SQLite, отдельный production-процесс и перезапуск, сохранность профиля/доски/заметок/сеанса, а также импорт, хранение PGN, сохранение анализа и повторный вход. Рабочая база и исходная SQLite не изменяются.

## Проверено на настоящих данных

Прямое обращение к публичному API Chess.com выполнено скриптом `scripts/test-live-chess.ts`, без подмены ответов. Для прокси среды Codex использован `NODE_USE_ENV_PROXY=1` (уже в команде `test:live`).

- Профиль: `alexander_gusev`; текущий Rapid в полученной статистике: **1437**. Это снимок на момент запроса, не постоянная величина.
- Архив: **2026/10**, импортировано **144 настоящие Rapid-партии** в изолированную SQLite.
- Повторная обработка того же архива: **0 новых записей**.
- Реальная партия: https://www.chess.com/game/live/185802073828 — **99 полуходов**, PGN воспроизведён chess.js.
- Настоящий WASM Stockfish обработал **100 позиций**, включая начальную и конечную. Подтверждены количество точек и последняя точка графика, сохранение результата и точное восстановление после выхода/входа.
- На локальной PostgreSQL повторный реальный браузерный сценарий прошёл на desktop и mobile Chromium. В последнем прогоне само вычисление заняло примерно **8,3 и 8,2 секунды** при 100 мс/позицию, глубине до 14; отдельные позиции завершаются раньше лимита. Это измерение этой машины, не обещание скорости телефона.

Живой скрипт сохраняет неизменённый ответ выбранной партии в игнорируемый `.verification/real-chesscom.json`. Браузерные сценарии затем используют этот реальный снимок через отдельный тестовый сервер, чтобы воспроизводимо проверить интерфейс и сохранение. Они не выдают тестовый сервер за новое прямое обращение браузера к Chess.com. В рабочем сервере такой подмены нет. Отчёты движка записываются в `.verification/stockfish-real-*.json` и не попадают в Git.

Для повторения с нуля: `npm run build`, `npm run test:live`, затем `npm run test:postgres`. Если внешняя сеть/API недоступны, `test:live` завершается ошибкой, а не переключается на искусственные данные. PostgreSQL-прогон добавляет реальные браузерные сценарии только при наличии снимка от успешного живого импорта; без него выполняются основные 18 + 8 проверок.

## Проверено на контролируемых тестовых примерах

`tests/helpers/chess-fixture.ts` содержит явно искусственные PGN и HTTP-ответы только для тестов. На них проверяются: Rapid отдельно от Blitz, точные контроли, фильтры, отсутствие дублей, обработка 429 и сохранность старых данных, проверка владельца и вариантов анализа. На известном матовом примере реальный Stockfish находит `d8h4`; поддельного движка нет.

Браузерные тесты проверяют запуск Worker только по кнопке, остановку, сохранение частичного результата, готовый анализ после повторного входа, нотацию, превращение, допустимые ходы и сохранность позиции при сетевом сбое. Перетаскивание проверено мышью и настоящими сенсорными событиями CDP. Проверяется отсутствие переполнения рабочей области и переключение мобильных панелей. Унаследованные проверки первого этапа проходят.

## Границы проверки

Удалённая рабочая Neon и обновлённый публичный Render в этой сессии непосредственно не проверялись: нет доступа к панели существующего сервиса и его секретам. Обновление выполняется по [инструкции](STAGE_2.md). Результаты локальной PostgreSQL не выдаются за облачный deploy.

Не проверялись все исторические месяцы, физические Safari/iOS и Firefox, все возможные сбои Chess.com. Мотивы ошибок определяются осторожной эвристикой, не языковой моделью и не официальной метрикой точности Chess.com. Третий этап не реализован. Подробные ограничения бесплатной инфраструктуры и короткого анализа перечислены в инструкции второго этапа.
